```ts

```

### 4.2 Модели контента (`src/data/`)

Все пользовательские тексты в данных — объекты с двумя языками.

```ts
type Localized = { ru: string; en: string };

type ServiceCategory = 'therapy' | 'hygiene' | 'implants' | 'orthodontics' | 'aesthetics' | 'kids';

type Service = {
  id: string;
  category: ServiceCategory;
  title: Localized;
  description: Localized;
  priceFrom: number;          // в рублях
};

type Doctor = {
  id: string;
  name: Localized;
  specialty: Localized;
  experienceYears: number;
  photo: string;
};

type Case = {                 // до/после
  id: string;
  serviceId: string;
  before: string;
  after: string;
  duration: Localized;
};

type Review = {
  id: string;
  author: Localized;
  rating: 1 | 2 | 3 | 4 | 5;
  text: Localized;
  serviceId: string;
};

type FaqItem = { id: string; question: Localized; answer: Localized };
```

Объём контента: 18–24 услуги (3–4 в категории), 4 врача, 4–6 кейсов, 6–8 отзывов, 6–8 вопросов FAQ.

Цены форматируются через `Intl.NumberFormat` с валютой RUB по правилам текущей локали: «от 3 500 ₽» / «from ₽3,500».

### 4.3 Изображения

- Пока реальных фото нет, используется компонент `ImagePlaceholder` — аккуратный блок в цветах сайта с иконкой, точно такого же размера и пропорций, как будущее фото.

- После замены плейсхолдеров на реальные файлы в `public/images/` код менять не нужно (пути заданы заранее в данных).

## 5. Форма записи

### 5.1 Поля и валидация (zod)

| Поле | Тип | Правило |
|---|---|---|
| name | string | обязательно, 2–50 символов |
| phone | string | обязательно, валидный международный номер, хранится в формате E.164 |
| serviceId | string | необязательно, из списка услуг |
| doctorId | string | необязательно, из списка врачей |
| date | string (YYYY-MM-DD) | необязательно, не раньше сегодня; нативный `input type="date"` |
| timeOfDay | `'morning' \| 'day' \| 'evening'` | необязательно |
| comment | string | необязательно, до 500 символов |
| consent | boolean | обязательно `true` |
| website | string | honeypot, должно быть пустым (скрытое поле) |
| locale | `'ru' \| 'en'` | заполняется автоматически |

Одна и та же схема используется на клиенте и на сервере. Тексты ошибок берутся из переводов.

### 5.2 Предзаполнение
- Кнопки «Записаться» в карточках услуг и врачей сохраняют `serviceId` / `doctorId` в `store/booking.tsx` (React Context) и плавно прокручивают к форме.
- Форма подставляет выбранные значения.

### 5.3 Состояния формы
- `idle` → `submitting` (кнопка заблокирована, спиннер) → `success` (сообщение «Спасибо! Мы перезвоним в течение 15 минут» и кнопка «Отправить ещё») или `error` (сообщение и предложение позвонить по телефону).

## 6. API: `POST /api/booking`

**Логика:**
1. Проверить ограничение частоты: не более 3 заявок с одного IP за 10 минут → иначе `429`.
2. Если honeypot `website` заполнен → вернуть `200` без отправки (бот не должен понять, что его поймали).
3. Провалидировать тело zod-схемой → при ошибке `400` со списком ошибок.
4. Отправить сообщение в Telegram → при ошибке `502`.
5. Вернуть `200 { ok: true }`.

**Сообщение в Telegram** (HTML parse mode, пользовательский ввод экранировать; услуга и врач — названиями на русском, не id):
```
🦷 Новая заявка с сайта
👤 Имя: …
📞 Телефон: …
🩺 Услуга: …
👨‍⚕️ Врач: …
📅 Дата: … (утро/день/вечер)
💬 Комментарий: …
🌐 Язык: RU
```

**Переменные окружения** (`.env.local` и Vercel; в репозитории — только `.env.example` с пустыми значениями):
```
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
NEXT_PUBLIC_SITE_URL=
```
Токен используется только на сервере и никогда не попадает в клиентский код. Если переменные не заданы, API возвращает `500` с понятным сообщением в логах, а сайт продолжает работать.

Ограничение частоты: простой in-memory счётчик. При росте нагрузки заменяется на Redis/Upstash.

| Компонент | Поведение |

**Типографика:** Manrope; H1 48/56 px (мобильный 32/40), H2 36/44 (мобильный 26/34), текст 16/26.
**Скругления:** карточки 16 px, кнопки 12 px. **Контейнер:** max-width 1200 px, отступы 16 px на мобильных.
**Логотип:** SVG-иконка зуба + текст «BrightSmile Dental», компонент `Logo`.

## 9. SEO и производительность

- `generateMetadata` для каждого языка: title, description, Open Graph, `alternates.languages` (hreflang).
- JSON-LD `Dentist` из `site.ts`: название, адрес, телефон, часы работы, рейтинг.
- `sitemap.ts` со всеми локалями, `robots.ts`, favicon.
- `next/image` с размерами и `priority` только для hero; ленивая загрузка остальных.
- Шрифт через `next/font` (без скачков вёрстки).
- Тяжёлые интерактивные компоненты — клиентские, всё остальное — серверные компоненты.
